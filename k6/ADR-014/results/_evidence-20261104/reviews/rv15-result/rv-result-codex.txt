   781	- **크기**: 예약 N행(CONFIRMED · 좌석마다 1행 — 인덱스 크기 최대 쪽 · 보수적 선택) · N ∈ {1,000,000 · 5,000,000}(D-5 — ADR-002 규모 축 100만 · S5 상단 500만 — docs/adr/ADR-002-db-baseline.md:769) · 크기마다 3회.
   782	- **절차**(`scripts/v12-build.sh`): 새 DB(V1~V13 — 앱 current로 한 번 띄워 Flyway 적용) → 앱 정지(다른 쓰기 없음) → 인덱스 DROP → 시드(좌석 N + 1,000 · 예약 N · ANALYZE) → ① 세션 A: `BEGIN; CREATE UNIQUE INDEX uq_reservation_confirmed_seat ON reservation (seat_id) WHERE status = 'CONFIRMED'; COMMIT;`(V12 파일과 같은 문장 — Flyway 기본 = 스크립트마다 트랜잭션 하나) · 50ms 뒤 세션 B: 예약 1행 INSERT(쓰기 하나 — 시작 · 끝 `clock_timestamp()`) → ② DROP 뒤 `CREATE UNIQUE INDEX CONCURRENTLY` + 같은 탐침 B → 끝에 `indisvalid AND indisunique` 확인(둘 다).

   784	- **판정**(`summarize.py --v12`): **계획한**(v12-build.sh가 남긴 `v12-plan.json` — 크기 목록 · 반복) 가장 큰 N의 3회 쓰기 차단 최대 ≤ 2,000ms(D-5 — ADR-013 :186) → **트랜잭션 안 판 유지** · > 2,000ms → **CONCURRENTLY 판 후속**(V12 `.conf` `executeInTransaction=false` + `indisvalid` 기동 검사 · §설계-4 재시도 절차 — 새 task). **계획한 모든 (크기, 반복) 자리**마다 파일 · 시드 종료 코드 0 · 시드 실측 행 수(예약 = N · 좌석 = N + 1,000) · 값 · indisvalid가 맞아야 한다 — 하나라도 빠지면 판정 불가(관측 파일 중 가장 큰 N으로 판정하지 않는다 · M15-7 · M15-8). **필수 값(fix3 M15-31)**: 트랜잭션 판 `build_ms` · `probe_blocked_ms` · `probe_started_inside` · **CONCURRENTLY 판 `build_ms` · `probe_ms` · `probe_started_inside`** · 두 판 `valid` — 하나라도 없으면(측정 오류 `error` 포함) 판정 불가. **이 판정은 캠페인 완료 관문이다(M15-30 — 측정-8 끝 'V12 관문')**: 단계 누락 · 실패 · 판정 불가면 결론 옆 'V12 판정 불가' · 교체면 '운영 적용 전 V12 판정 필요'. CONCURRENTLY 쪽 탐침 대기(쓰기를 막지 않아야 한다)와 생성 시간도 함께 적는다(Flyway 비트랜잭션 실패 이력 · `flyway repair`는 #5의 나머지 몫 — CONCURRENTLY 판을 고를 때 그 task가 잰다).
   785	- **로컬 신호(.164 값 아님 · 판정에 쓰지 않는다)**: 이 PC 로컬 PG 16(tmpfs 아님)에서 100만 행 3회 생성 582~670ms · 탐침 대기 532~637ms · CONCURRENTLY 768~874ms(탐침 7~9ms). 선형이면 500만 행 약 3초 → 2초 문턱을 넘을 수 있다 — 결과가 'CONCURRENTLY 판 후속'으로 갈 가능성을 메인이 미리 알아 둔다.

def much_higher(xv, yv):
