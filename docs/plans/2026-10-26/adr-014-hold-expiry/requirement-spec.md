## 1. 목표·대상 (필수)

`seat-reservation-lab`(main-app · k6 하네스 · ADR-014 문서)에서 홀드 만료 방식 A·B·C·D를 설정 손잡이로 구현하고, 측정 전에 고정한 규칙으로 .164에서 비교해 기본 방식을 결정한다(이기면 기본값 교체). ADR-014 §실험 결과·§결정이 채워지면 끝.

## 2. 경계·불변식 (필수)

- **좌석 이중 판매 0**: 어떤 방식에서도 한 좌석에 활성 홀드(만료 전) 또는 확정이 둘 이상 생기지 않는다.
- **만료 판정 단일 규칙**: "활성 홀드" = `expires_at > DB now()`. 선점·확정·조회·배치·카운터 회수가 같은 규칙을 쓴다(앱 Clock으로 만료를 판정하지 않는다). **예외(§10 R1)**: A(sweep)는 지금 코드 그대로 앱 Clock — 단일 규칙은 B·C·D 경로에만.
- **1인 매수 한도**: 활성 홀드 수 ≤ `max-per-user`. B·C·D에서 만료된 홀드는 선점 트랜잭션 안에서 회수하고 카운터를 내린 뒤 판정한다 — 회수와 카운터 감소는 같은 트랜잭션(부분 반영 0).
- **카운터 정합**: ADR-009·012 대조 기준(카운터 = 홀드 행 수 + 확정 — 만료 무관 · §10 R2)이 새 방식에서도 성립한다 — 오탐 복구 0 · 끝 불일치 0. 매수 판정은 선점 트랜잭션의 회수 뒤 카운터로 한다(그 순간 = 활성 홀드 수 + 확정).
- **배치 경합**: 배치가 방금 재선점된 좌석을 되돌리지 않는다(초안 가설 3을 측정으로 확인 · 설계로 차단).
- **만료 뒤 확정은 거부**(같은 규칙). 확정 원자성·외부 결제는 범위 밖(ADR-015·016).
- **기존 동작 보존**: 손잡이 기본값을 바꾸기 전까지 기존 기본값(A) 동작·기존 테스트 결과는 그대로.
- **적용 범위(메인 제안 — 설계 선검증에서 확정)**: B·C·D는 기본 경합 방식(`pessimistic-nowait`)과 기본 매수 방식(`counter-upsert-precheck`)에서 구현한다. 그 밖의 조합에서 A 이외 방식은 기동 거부(조용히 A로 돌지 않게).
- 스키마 변경은 새 마이그레이션 번호로만 · 추가형 우선(ADR-013 §7.3).

## 8. load-bearing 가정

1. DB `now()`(트랜잭션 시작 시각)로 판정해도, 같은 트랜잭션 안의 선점·회수가 앱 Clock 판정과 같은 결과를 낸다 — 단 긴 트랜잭션에서는 `now()`가 고정이므로 `clock_timestamp()`와의 차이를 착수 직후 스모크로 확인.
2. D의 "좌석당 활성 홀드 1개"를 부분 유니크 인덱스 없이(시간 조건) 좌석 행 잠금 또는 홀드 행 upsert로 강제할 수 있다 — 설계 선검증 대상.

## 10. 재합의 (2026-10-26 — 설계 초안 열린 질문)

- **R1 (Q1)**: A는 앱 Clock 유지 — DB `now()` 단일 규칙은 B·C·D에만(기존 테스트가 `MutableClock`으로 만료를 만든다 · 51곳 20파일). 사용자 '권장안' 선택.
- **R2 (Q2)**: '카운터 = 활성 홀드 수'를 '카운터 = 홀드 행 수 + 확정(만료 무관 — 지금 대조 정의) · 매수 판정은 회수 뒤 카운터'로 고쳐 읽는다 · reconcile-core 무변경. 사용자 '권장안'.
- **R3 (Q3)**: B·C·D 확정에 최소 가드(좌석 `FOR UPDATE` 뒤 '내 홀드 활성 · 다른 활성 홀드 없음') — 이중 판매 0의 필요조건 · A 확정·원자성 일반 해법은 ADR-015. 사용자 '넣음'.
- **R4 (Q11·Q12)**: 좌석 맵 `GET /api/schedules/{id}/seats` → `[{seatId, section, rowNo, seatNo, status}]` 페이지 없음 · A ↔ B·C·D 전환은 ①(멈추고 바꾸기)만 + 되돌리기 전 정리 SQL · 무중단 방식 전환·혼재 감지 장치는 범위 밖(NEXT 후보). 사용자 '권장안대로'. **선검증 뒤 메인 판단(DS14-2)**: ①만 허용을 B·C·D 사이 전환(D↔B·C)으로도 넓힌다(더 엄격 — 저장 HELD 의미가 방식마다 달라 섞이면 좌석 맵이 틀린다) · 모든 방향 정리 = 좌석 기준 재계산 — 사용자 보고 대상.
