# ADR-003: 1인 최대 2매 — 같은 사용자 동시 요청

- 상태: 가설 (Hypothesis) — 미측정
- 대응: Load Profile "1인 최대 2매" (파생 이슈)
- 선행: ADR-000, ADR-001

## 문제

기준선은 `(사용자, 회차)의 홀드 수 + 확정 예약 수 조회 → 2 미만인지 비교 → 홀드 저장`이다. 같은 사용자가 탭 여러 개나 매크로로 동시에 요청하면 모두 같은 개수를 읽고 통과한다. 잠글 대상이 아직 없는 행(팬텀)이라 행 락으로도 막을 수 없다.

## 가설

- 같은 사용자가 서로 다른 좌석 N개를 동시에 선점하면 2매를 초과한다.

## 재현 시나리오

- k6: 사용자 1명이 서로 다른 좌석 10개를 동시 선점

## 선택지 후보

| 방식 | 동작 | 예상 단점 |
|------|------|----------|
| 한계로 수용 | 단순 COUNT | 동시 요청 시 초과, 사후 검증으로만 탐지 |
| PG advisory lock | `pg_advisory_xact_lock(회차, 사용자)` → COUNT → 저장 | Postgres 전용, 락 키 공간 관리 |
| 쿼터 행 `FOR UPDATE` | (사용자, 회차) 쿼터 행에 행 락 | 테이블 추가, 첫 요청 시 행 생성 경합 |
| 카운터 조건부 UPDATE | `cnt + n <= 2` | 만료 시 카운터를 내려줄 주체 필요 — 만료 방식(ADR-004)에 종속 |
| SERIALIZABLE | DB가 충돌 감지 | 재시도 로직, 오픈 시점 실패율 |

- 검토 포인트: 같은 사용자만 직렬화하고 다른 사용자끼리는 막지 않는가 · 좌석 경합 경로(ADR-002)와의 락 순서
