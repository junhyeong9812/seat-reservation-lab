# ADR-001: 정합성 판정과 관측 하네스 (Q7)

- 상태: 가설 (Hypothesis) — 미측정
- 대응 질문: Q7 "테스트가 끝났을 때 좌석 상태는 정말 정확한가?"
- 선행: ADR-000

## 문제

k6가 보는 것은 HTTP 상태 코드와 지연시간뿐이다. 같은 좌석에 1,000명이 모두 `201`을 받아도 k6는 통과로 본다. **"성공 응답"은 "정합성"이 아니다.** 이후 모든 ADR이 "해결됐다"를 말하려면 공통 판정 기준(oracle)과 반복 가능한 부하 하네스가 먼저 있어야 한다.

## 가설

- 기준선에서 부하 후 k6 결과는 대부분 성공으로 보이지만, 판정 SQL은 불일치를 잡아낸다.

## 판정 기준 후보 (부하 종료 직후 실행)

| 항목 | 기대값 |
|------|-------|
| 좌석당 홀드 행 수 > 1 인 좌석 | 0 |
| 좌석당 `CONFIRMED` 예약 > 1 인 좌석 | 0 |
| `RESERVED` 좌석 수 = `CONFIRMED` 예약 수 | 일치 |
| `HELD` 좌석 수 = 활성 홀드가 있는 좌석 수 | 일치 |
| 만료됐는데 `HELD`로 남은 좌석 (배치 주기 경과 후) | 0 |
| (사용자, 회차)당 홀드 + 확정 예약 > 2 | 0 |
| 성공 응답(201) 수 vs 실제 홀드 소유 수 | 일치 |

## 선택지 후보

- 판정 방식: SQL 스크립트 / 검증 엔드포인트 / 배치 잡
- 부하 하네스: k6 시나리오 파일 고정 · 시드 데이터 고정 · 실행 환경(CPU·커넥션 풀) 기록 · N회 반복
- 결과 기록: 선택지별 커밋 해시 + k6 요약 + 판정 결과
