## 1. 목표·대상 (필수)

`seat-reservation-lab`에서 ADR-016 설계-8 · 9의 측정을 끝까지 한다 — 모형 스크립트로 θ · W · M을 고르고, `k6/ADR-016/` 하네스로 .164에서 paid-flow · race · cost 셀을 재서, 고르는 규칙(G-정합 · G-모형 · G-목표 · G-비용)으로 ADR-016 §실험 결과 · §결정을 쓴다. 끝 = 결정 문서 + 측정 로그 · 결과 폴더 커밋(앱 기본값 변경은 사용자 확인 뒤 별도 커밋 — ADR-015 D-6 선례).

1. **앱 코드 — θ < TTL 기동 검사**(`HoldStrategyStartupCheck.checkConfirmConfig`): `mode.paymentStartEnabled`면 `θ < seat.hold.ttl` — 어기면 거부(키 이름 · 값을 메시지에). 기본값(θ 0 · TTL 5분)은 통과.
2. **모형 스크립트** `k6/ADR-016/scripts/model16.py`(서버 없음 · 표준 라이브러리만 · 시드 고정):
   - 분포: `T` ~ U[30, 240]초(민감도 U[30, 120] · U[60, 270]) · `D` ~ 로그정규(중앙값 m ∈ {30, **45**, 60} · σ ∈ {0.7, **0.94**, 1.2}) · CAP ∈ {**10**, 30}분(D > CAP = 결제 실패) · δ̂(아래 3의 정의 — 상한) · 시계 오차 = 회차 `err_ms`(상한). 판정 입력이 없으면 0으로 채우지 않고 결측(무효).
   - 정책: ①(payment-start 없음) · ①+ⓑ(θ) · ④(W · θ) · 각 ⓒ 켬/끔(M — 하네스 마감 = min(응답 수신 시각 + `payWithinSeconds`, 절대 `payBy`를 PC 시각으로 옮긴 값 − err_ms) — 수신 + 상대값만 쓰면 전송 지연이 내림으로 버린 소수 초보다 클 때 서버 `payBy`를 넘는다(DV16-R1) · 결제가 마감을 넘으면 결제 실패 · 모형도 같은 식).
   - 고르는 규칙(§0): ①+ⓑ θ = '결제 전 거부 + 결제 실패 ≤ 5%' 안에서 억울 최소 · ④ W = CAP + M + 여유(여유 = 배치 주기 + 측정 전 고정 값) · ④ θ = M · M = 스모크 δ̂ + err_ms의 p99.9를 덮는 값(초 올림). 모든 ① · ④ 구성은 `M ≤ θ < min(TTL, W)`(앱 기동 검사 — plan16 dry-run이 렌더마다 확인).
   - 출력(정책 × 분포 · CAP 10 / 30분마다): 억울 · 결제 전 거부 · 결제 실패 비율 · 홀드 수명 분포(p50 · p99 · 최대).
   - **두 함수(M16-1)**: `predict(T, D, 매개변수, 시각들)` = 세션의 예상 분류 · `classify(세션 응답열 · 끝 상태)` = 관측 분류(하네스 요약기와 공유). selftest가 `predict = classify(흉내 응답)`을 확인하고, G-모형이 `predict` 대 실제 `classify`를 세션마다 대조한다.
3. **하네스** `k6/ADR-016/`(ADR-015 lib · 동결 · 해시 · 시작 조건 · 무효 재측정 구조 재사용 — `lib15.sh` · `lib14.sh` · `lib.sh`를 source · 실제 눈금에 맞게 grace(≥ T 최대 + CAP + 여유) · 수렴(≥ max(TTL, W) + 배치 + 여유) · 미리 만든 VU(도착률 × 세션 수명 상위값)를 plan16에서 다시 계산 — TTL 30초 상수 재사용 금지):
   - **paid-flow 셀(실제 눈금 · TTL 5분 · 배치 10초 = 앱 기본)**: 세션 = 선점 → `T` → (ⓑ · ④면 payment-start) → `D` → 확정 1회. 흐름은 **세션 번호 mod 흐름 수로 교차 배정**(시간 효과가 흐름과 섞이지 않게) · 흐름당 회차 1,100(3회 합 3,300). `T` · `D`는 (회차, 세션 번호) 시드. 긴 간격(≥ 50초) 앞 요청은 `Connection: close`(ⓑ 없는 흐름은 선점 요청이 T + D를 넘긴다 — lib14 closeBeforeLongThink). conditional 회차 = {ⓑ 없음 · ⓑ} × {ⓒ 끔 · 켬} + **ⓒ 경계 흐름** · ④ 회차 = {ⓒ 끔 · 켬} + **ⓒ 경계 흐름**.
   - **ⓒ 경계 흐름**(DV-3): 흐름당 회차 수백 세션(값은 고정 커밋) · 결제 시간을 무작위로 두지 않고 하네스 마감(위 min 식) 직전 격자(마감 − x · x ∈ 고정 격자 · 일부는 마감 뒤)에 확정을 보낸다 · 판정 = 마감 안에 보낸 확정의 거부 0(M이 δ + 시계 차를 덮음) · 마감 뒤 송신은 하네스가 결제 실패로 보내지 않는다(대조용 계수만).
   - **재선점**: paid-flow 세션의 ρ = 0.5에 다른 사용자가 원래 만료 `e` 둘레에서 같은 좌석을 재선점 시도 · 지표 = 좌석을 결국 못 얻은 재선점 비율 · 좌석이 풀리기까지의 시간(409 횟수는 시도 일정이 만드는 값이라 판정에 쓰지 않음 · DV-11). 억울 수에는 영향 없음(설계-9.1 — 재선점 201은 배치가 지운 뒤뿐).
   - **세션 분류(결정표 — 입력 = 요청별 (status, code) · 끝 상태 · 출력 = 5갈래 + 무효 사유 · DV-5)**:
     - 선점 비201 · 본문 결함 = 무효(hold-fail · ADR-015 선례).
     - payment-start 계약 거부(① 409 HOLD_EXPIRED · 404 · ④ 409 too_late 등 계약 쌍) = **결제 전 거부** · payment-start status 0 · 5xx · 계약 밖 · 200 본문 결함 = ADR-015 규칙(시간 초과 · 5xx = 방식 실패 G-F · 그 밖 코드 0 = 하네스 무효).
     - D > CAP 또는 ⓒ 마감 초과 = **결제 실패**(확정을 보내지 않음).
     - 결제 성공 세션의 최종 분류는 **끝 상태 DB**로: 그 paymentUid의 CONFIRMED 예약이 있으면 **성공** · 없으면 **억울**. 확정 응답은 허용 목록으로 교차 확인 — 200 ↔ 예약 있음 · 404 HOLD_NOT_FOUND · 409 HOLD_EXPIRED · 409 SEAT_NOT_HELD ↔ 예약 없음. 어긋남(200인데 예약 없음 · 거부인데 예약 있음) = G-정합 실패. 확정 403 · 5xx · status 0 · 계약 밖 = ADR-015 규칙.
     - 흐름별 계획 세션 수 = 분류된 세션 수(gracefulStop · dropped 포함 차 0) — 아니면 무효(M16-4).
   - **race 셀**: ADR-015 race 셀 그대로(plan15 race 값 · TTL 30초 · confirm-contention.js · ① · ④ — plan15 회전에서 두 모드만 뽑고 해시 대조 유지) — ADR-015 ④ race 판정 불가를 같은 규칙으로 메운다.

   - **세션 기록(paid-flow만)**: 세션마다 k6 CSV에 결과 행(흐름 · 세션 번호 · T · D · 요청별 status/code · 송신 · 수신 시각 · payWithinSeconds · paymentUid).

## 2. 경계·불변식 (필수)

- **M16-1** 세션 분류는 결정표 하나로 정한다 — `classify`는 하네스 요약기와 모형이 공유하고, `predict(T, D, 매개변수)` = `classify(흉내 응답)`(selftest로 고정).
