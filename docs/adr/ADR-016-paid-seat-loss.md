## 문제

ADR-015 ① `conditional`은 늦은 확정을 **명확한 거부**로 바꿨다(500 · 틱 전체 롤백 → 409 `HOLD_EXPIRED` 또는 404 `HOLD_NOT_FOUND`). 거부가 확실하니 환불도 확실해졌지만, **거부되는 사람의 수는 그대로다**. 결제(외부 — 이 랩 범위 밖)가 홀드 만료보다 늦게 끝나면 그 사용자는 돈을 낸 뒤 좌석을 잃는다.

- **억울한 사용자(정의 — 초안)**: 결제를 끝낸 뒤 보낸 확정이 거부된 세션. 거부 코드 = 409 `HOLD_EXPIRED`(만료 · 배치 전) · 404 `HOLD_NOT_FOUND`(배치가 지운 뒤) · 409 `SEAT_NOT_HELD`(V12 위반 매핑 — 같은 좌석 남의 확정).
- **억울하지 않은 실패(구분)**: 결제를 **시작하기 전에** 거부된 세션. 좌석은 못 얻지만 돈이 빠지지 않는다. 예방책은 대개 억울한 실패를 이 쪽으로 옮기는 것이다. 그래서 두 수를 함께 잰다.

## 가설

- 억울한 실패는 '결제 시작 시점의 남은 TTL'과 '결제에 걸린 시간'의 경주다. 결제 시작 때 남은 시간을 보장하거나(ⓐ), 모자라면 시작을 막으면(ⓑ) 수가 줄어든다.
- ⓐ는 홀드를 늘리므로 좌석 회전이 느려지고 DB 쓰기가 늘어난다(ADR-015 cost DB CPU ④/① 1.119 — 비겹침). ⓑ는 읽기 하나라 싸지만, 결제 시작 거부(억울하지 않은 실패)를 늘린다.

## 설계-3 측정 설계 — 뼈대 (고정값은 측정 task)

- **부하 모델**: 선점 → 생각 시간 → 결제(흉내 — 걸리는 시간 분포 · 꼬리가 긴 분포) → 확정. 결제 시간 분포가 결론을 좌우한다 — 가정을 측정 전에 고정한다(열린 질문 Q3).
- **지표(판정)**: ① 억울한 실패 비율(결제 끝 세션 중 확정 거부) ② 결제 전 거부 비율 ③ 좌석 회전(만료 → 재선점까지 · 판매 완료 시간) ④ 비용(확정 p99 · 선점 p99 · DB CPU — ADR-015와 같은 세 지표).
- **셀 후보**: ①(대조군) · ① + ⓑ · ④ · (ⓒ는 결제 시간 상한을 흉내 분포의 절단으로).
- **고르는 규칙(초안)**: 억울한 실패가 대조군보다 확정적으로(범위 비겹침) 낮은 후보 중, 결제 전 거부 · 비용이 문턱을 넘지 않는 가장 단순한 것. 문턱은 측정 전에 고정한다.
- ADR-015 ④ race 판정 불가(유효 2/3)는 EOF 수정 뒤 재측정으로 메운다(설계-5).

## 설계-4 보상 설계 — 판정 기준까지 (구현 = ADR-017)

- **고아 결제 기록**: 거부된 확정의 `paymentUid`를 남긴다(지금은 어디에도 없다). 후보 = 거부 기록 표(홀드 · 사용자 · paymentUid · 거부 코드 · 시각) — 같은 `paymentUid` 재시도의 멱등 응답과 함께 정한다(ADR-015 Q11 남은 몫).
- **판정기(ADR-001) 확장 후보**: '결제 uid는 있는데 확정 예약이 없는 건' = 고아 결제 수 — 측정 끝 상태에서 센다(억울한 실패 지표와 교차 확인).
- **보상 방식 후보**(ADR-017이 고른다): 즉시 환불 · 대체 좌석 제안 · ⓓ 승인 취소.

## 설계-5 첫 단계 — 선점 · 재선점 EOF 하네스 수정

- **관측**(ADR-015 결과-4): 캠페인 무효 6회 모두 `k6-code0` — 회차마다 선점 · 재선점 1~2건이 EOF(k6 error_code 1000) · 확정 0건 · ④ race 시도 7 중 5 무효.
- **가설(미검증)**: 반복 **사이**에 쉬던 VU가 Tomcat 유휴 한도(60초 — ADR-014 06c)를 넘은 연결을 재사용한다. 29e09aef로 미리 만든 VU가 늘어 VU 하나가 쉬는 시간이 길어졌다. ④는 세션이 길어(연장 창) 더 잦다.
- **재현 먼저**(ADR-014 06c 방식): 반복 사이 유휴를 60초 넘게 만든 작은 시나리오로 EOF를 재현 → 처방 뒤 0건.
- **처방 후보**: (가) 반복의 마지막 요청에 `Connection: close`(lib14 `closeConn` 재사용 — 다음 반복은 늘 새 연결) (나) k6 옵션 `noVUConnectionReuse`(반복 사이 연결 재사용 끔 — 한 줄). 둘 다 반복 첫 요청에 연결 수립 비용이 붙는다 — 선점 p99에 들어가므로 ADR-015 수치와 직접 비교하지 않고 대조군을 같은 하네스로 다시 잰다.
- **처방(결정 — Q6)**: (가) + (나). 확정 · 짝 확정 · 재선점 마지막 시도에 `Connection: close` · `options.noVUConnectionReuse: true`(`k6/ADR-015/scenarios/confirm-contention.js`). 재현 증거 = `k6/ADR-015/results/_evidence-20261107/16-eof-repro/`(conditions.tsv — 변형 넷 · 조기 종료 30% · TIME_WAIT 최댓값).
