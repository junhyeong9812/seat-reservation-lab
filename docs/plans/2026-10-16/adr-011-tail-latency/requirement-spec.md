## 1. 목표·대상 (필수)

seat-reservation-lab에서 측정용 앱 기준(ADR-010 — 2g + 세대형 ZGC) 위의 꼬리 지연 원인을 가린다: ① 약 26초 간격 50~150ms 튐의 출처(k6 부하 생성기 쪽인지 서버 쪽인지 → 구체 원인) ② 4g ZGC 추가 튐이 첫 접근 페이지 폴트인지(`-XX:+AlwaysPreTouch` 비교) ③ 30분 이상 장시간에서 2g ZGC가 안정적인지(메모리·꼬리 추세). 결과를 `docs/adr/ADR-011-*.md`에 쓰고, 원인별 대처(측정 기준·하네스 변경)를 정해 반영하면 끝.

## 2. 경계·불변식 (필수)

- 하네스 새 손잡이는 지정하지 않으면 렌더·계획이 이전과 같다(ADR-009·010 재현). — **범위 명시(2026-10-16, 하네스 리뷰)**: '계획' = 캠페인 계획 파일(conditions.txt·order.txt)과 compose 렌더. 회차 plan.json·meta.json에는 새 키가 덧붙는다(ADR-010과 같은 방식 — 실행 동작에는 영향 없음).
- 측정 기준 = 2g + 세대형 ZGC(ADR-010) — 원인 실험은 이 위에서, 대조는 같은 캠페인 안에서.
- 가설·판정 기준은 실험 전에 ADR에 고정·커밋한다(읽기 전용 분석 결과로 가설을 세운 뒤).
- 원인을 '확정'하려면 켜고 끄는 실험(원인 후보를 없앴을 때 튐이 사라지고, 되돌리면 돌아옴)이 있어야 한다. 시각 대조만으로는 '후보'까지.
- 앱 코드 변경(서버 쪽 처리 시간 측정 등)은 측정 전용으로, 기본 동작·응답 계약을 바꾸지 않는다.
