## 0. 요구사항 원문 (인터뷰 기록)

- 원문: "지금 최소인덱스도 생성을 안했구나. 그럼 다음 실험은 인덱스부터 추가하고 진행하는게 맞겠네" → "우선 인덱스와 커넥션 풀을 늘려서 l4와 l2에 대해서 타임아웃 빈도를 우선 확인하는게 우선 아니야? … 이 통신자체 문제 오류를 db차원에서 인덱스와 커넥션 풀은 확장하는게 맞다고 보는데 그게 제대로된 기준이 될 꺼 같은데 이게 adr2아닐까 지금의 adr2는 미루고?"
- 메인 의견(합의 전 전달): 인덱스는 먼저 하는 게 맞음(ADR-001 §4.3: 선점마다 `seat_hold` 전체 스캔 2회). 풀은 "늘리면 좋아진다"가 아니라 **실험 변수** — ADR-001에서 Hikari 대기 예외 0(풀은 병목으로 관측 안 됨), DB 2~4코어에 동시 쿼리를 늘리면 역효과 가능, 풀 크기가 S1 중복 수(=10)를 바꿀 수 있음.
- Q/A:
  - 풀: **인덱스 × 풀 전부**(10/20/40) → 시간 추정(약 58h) 보고 후 **인덱스 없음 쪽 축소**로 조정
  - 시나리오: S4 · S1 · S2 · S3 원본(이탈 0·20·50%)
  - 자원: **L2·L4**, 반복 **5회**
  - 번호: **새 ADR-002 + 기존 002~009를 003~010으로 밀기**(참조 갱신 포함)

## 1. 목표·대상 (필수)

`seat-reservation-lab`에서 **DB 차원 기준선 보정(일반 인덱스 추가 · 커넥션 풀 크기)의 효과를 L2·L4에서 실측**하고, 락 비교 ADR(구 ADR-002 → 새 ADR-003)이 쓸 **새 기준선 조합**을 정해 새 ADR-002에 기록하면 끝.

측정 매트릭스:

| 조건 | 풀 | 시나리오 | 단계 | 회차 |
|------|----|---------|------|------|
| 인덱스 있음 | 10 / 20 / 40 | S1 · S2 · S4 · S3 원본 × 이탈 0/20/50 | L2 · L4 | 5 |
| 인덱스 없음 | 20 / 40 | S1 · S4 | L2 · L4 | 5 |
| 인덱스 없음 (환경 동일성 확인) — **실행함: 범위 밖 → 아래 재측정으로 대체** | 10 | S4 | L2 · L4 | 2 |
| **인덱스 없음 (기준선 재측정, 2026-09-29 사용자 결정 "전 시나리오 재측정")** | 10 | S1 · S2 · S4 · S3 원본 × 이탈 0/20/50 | L2 · L4 | 5 |
| 인덱스 없음 | 10 | (전 시나리오) | L1·L2·L4 | ADR-001 결과 재사용 |
| **규모별** 인덱스 없음·있음 × 배경 10만·100만 | 10 | S1 · S4 | L2 · L4 | 5 |
| **S5 규모별 쿼리 비용**(DB 직접, pgbench) 인덱스 없음·있음 × 배경 0·1만·10만·100만·500만 | — | 선점 경로 쿼리 4종 | L2 · L4 | 조합당 1회(쿼리마다 반복 실행) |

→ 인덱스 있음 180회 + 인덱스 없음 40회 + 확인 4회 + 규모별 80회 = **304회 + S5, 약 49시간(추정)**

- **규모 축 추가 (2026-09-29 사용자)**: "더미데이터 몇백만개 만들지 않아? … 인덱스의 규모에 따른 성능 비교도 가능한 거 아니야?" → "부하 전체(S1·S4)도 규모별로" · 반복 5회 · 배경은 홀드·예약 같은 양.
- **배경 데이터**: 규모 N = 별도 배경 회차에 좌석 2N(HELD N — 홀드 1개씩 / RESERVED N — CONFIRMED 1건씩), 사용자는 측정 사용자와 겹치지 않음. 판정 위반 0에서 시작, 측정 회차의 동작은 그대로이고 테이블 행 수만 늘어난다. 배경 홀드는 측정 중 만료되지 않게 먼 미래 만료.

## 2. 경계·불변식 (필수)

- **인덱스는 유니크가 아니다.** 조회 속도만 바꾸고 중복을 막지 않는다 — 유니크 인덱스·제약은 락 비교 ADR(새 ADR-003)의 해결책 후보로 남긴다. 따라서 인덱스를 추가해도 S1 중복 선점·S2 매수 초과는 **막히지 않아야 한다**(막히면 무언가 잘못 들어간 것).
- **도메인·서비스·API 동작 불변** — 바뀌는 것은 스키마(인덱스 추가 마이그레이션)와 설정값(풀 크기)뿐. 기존 테스트 전부 green.
- **인덱스 유무는 설정으로 전환**한다: Flyway V2(인덱스)를 추가하고, 인덱스 없음 조건은 `spring.flyway.target=1`로 V1까지만 적용. 기본 실행은 최신(V2 적용).
- **측정 조건은 ADR-001과 같게**: 같은 서버·k6 PC·시나리오·시드·예열·타임아웃(30s)·Tomcat 설정. 달라지는 변수는 인덱스·풀뿐. 다른 것이 바뀌면 명시.
- **판정·근거 보존 규칙은 ADR-001 그대로**: DB 사실 기준 판정, 응답-DB 대조, 회차별 원시 결과 전부 보존, 표는 스크립트 산출, 미측정은 "미측정".
- **ADR-001 결과 재사용의 타당성은 확인한다**: 인덱스 없음·풀 10 S4를 L2·L4에서 2회씩 재측정해 ADR-001 범위 안에 드는지 본다. 벗어나면 재사용하지 않고 보고.

## 5. 검증 방법 (필수)

- 기존 테스트 전부 green + 인덱스 마이그레이션 테스트: V2 적용 후 인덱스 5개 존재·유니크 아님, `flyway.target=1`이면 인덱스 없음
- **인덱스가 중복을 막지 않음을 테스트로 확인**: 같은 좌석에 홀드 2행, 같은 좌석 CONFIRMED 2건 삽입이 V2에서도 성공(판정기 위반으로 잡힘)
- 실행 계획 확인: V2에서 1인 2매 확인·홀드 목록 로드가 Index Scan으로 바뀜
- 스모크: 각 조건(인덱스 있음/없음 × 풀 10/40) S1 1회 — 적용된 풀 크기(`hikaricp.connections.max`)와 인덱스 유무가 결과 파일에 기록되는지 · 배경 100만 시드 시간·판정 위반 0 확인 · S5 1조합
- 본측정: 계획(`plan.json`) 대비 누락 0, 실패 회차 명시
- ADR-002 표는 원시 결과에서 스크립트로 재산출

## 8. load-bearing 가정

1. 일반 인덱스만으로 선점 경로의 `seat_hold` 전체 스캔이 인덱스 스캔으로 바뀐다 — 착수 직후 실행 계획으로 실증.

## 9. 설계

### 9.1 인덱스 (Flyway `V2__add_indexes.sql`, 모두 유니크 아님)

| 인덱스 | 쓰는 곳 |
|--------|--------|
| `seat_hold(seat_id)` | 좌석의 홀드 목록 로드(애그리거트 컬렉션), FK |
| ~~`seat_hold(schedule_id, user_id)`~~ → `seat_hold(user_id)` | 1인 2매 확인 — 홀드 수 (2026-09-29 변경 합의: 쿼리 조건은 `seat_hold.user_id` + `product_seat.schedule_id` — 기존 인덱스는 앞 열이 조건에 없어 전체 스캔 그대로임을 스모크 실행 계획으로 확인, 사용자 "seat_hold(user_id)로 교체") |
| `seat_hold(expires_at)` | 만료 배치 조회 |
| `reservation(schedule_id, user_id)` | 1인 2매 확인 — 확정 예약 수 |
| `reservation(seat_id)` | FK |

### 9.2 하네스

- `k6/ADR-002/`에 ADR별로 자체 완결(사용자 원칙: ADR마다 사용한 부하 코드·파일 전부). ADR-001 하네스를 복사하고 변수만 추가:
  - compose: `POOL_SIZE`(기존), `FLYWAY_TARGET`(신규 — 인덱스 유무)
  - run.sh: 조건 축(`--index on|off`, `--pools "10 20 40"`), 셀별 적용 조건을 `meta.json`·`plan.json`에 기록
  - summarize.py: 조건(인덱스·풀)별 표 + ADR-001 재사용분 비교 열
- **"타임아웃 빈도"의 정의**: 응답 코드 0(클라이언트 30s 포기)·5xx 비율 — S1·S2는 선점, S3는 선점·확정 각각, S4는 단계별. 유령 확정(확정 200 − CONFIRMED)도 함께.
- 실행: ADR-001과 같이 별도 systemd 사용자 유닛(`ManagedOOMPreference=avoid`) + 스크립트 동결 + `--resume`
