## 1. 목표·대상 (필수)

seat-reservation-lab에서 ADR-011이 찾은 C(앱 안 대조)의 규모 한계를 푼다. ① 기존 F(별도 대조 앱)를 30분으로 재서 병목(앱 풀 대기 대 DB CPU)을 가른다. ② 바뀐 쌍만 짧은 주기로 대조하는 **증분 대조**를 구현한다 — 바뀐 쌍을 아는 방법 3가지(앱 메모리 집합 · `updated_at` DB 트리거 · `updated_at` 앱 문장) × 주기 2가지(1초·5초), 안전망 = 예산 있는 이어서 훑기(1분마다 DB 시간 2초 — 최근 2시간 창 먼저, 나머지 전체 커서) — 재합의 2번(1시간 → 10분 → 이것). ③ updated_at 방식은 별도 폴더의 **외부 대조 앱**(독립 앱 + Dockerfile + compose)으로도 만들어 .158에서 돌린다. ④ 30분 S4c4200 × 3회와 S3e(어긋남 주입 효과) × 3회로 판정하고, 성공 기준을 통과한 것 중 규칙대로 하나를 앱 기본값으로 바꾼다. 결과·선택지·고르지 않은 대안은 `docs/adr/ADR-012-*.md`에 쓰고, README 결정 목록을 ADR-011까지 최신화한다. **M4(Kafka + 읽기 복제본 + 외부 대조 앱 — CDC·아웃박스 비교)는 ADR-013으로 나눈다**: 이 작업에서는 ADR-013 문서에 배경·선택지(고른 것/고르지 않은 것)만 적고, 설계·구현·측정은 별도 작업 폴더의 명세로 시작한다(ADR-012의 M0~M3 결과를 기준선으로 쓴다).

## 2. 경계·불변식 (필수)

- **복구 경로는 그대로**: 어긋나 보인 쌍은 기존 `PairRepair`(쿼터 행 잠금 → 다시 세기 → 다르면 덮어쓰기, 맞으면 오탐 기록)로만 고친다. 증분 대조는 탐지만 새로 한다. 실제 값 정의 = 홀드 행 + CONFIRMED 예약(판정기·V6와 같음).
- **오탐 복구 0**: 증분이 본 쌍이 잠근 뒤 맞으면 덮어쓰지 않는다(지금과 같음).
- **새 손잡이를 지정하지 않으면 동작·렌더·계획이 이전과 같다**(ADR-009~011 재현) — 기본값 교체는 판정 뒤 별도 커밋. 측정 전용 앱 경로 주입은 loadtest 프로필에서만 켜지고 기본 꺼짐.
- **유실 없음**: 커밋된 모든 쿼터 변경은 적어도 한 번 증분 탐지 대상이 된다(기준점 DB 시계 · 창 겹침 · 메모리 집합은 커밋 뒤 등록·상한·넘침 기록) — ADR-012 §3.
- 마이그레이션: V1~V8 무변경. V9는 `user_hold_quota`에 열(+인덱스, 트리거 방식은 트리거 함수) **추가만** — 기존 행·쿼리 의미를 바꾸지 않는다. updated_at을 쓰지 않는 방식에서도 V9 적용 상태가 동작에 영향이 없어야 한다(트리거 비용은 트리거 조건에서만).
- 증분 대조와 안전망(C)이 같은 쌍을 동시에 고쳐도 결과가 맞아야 한다(둘 다 `PairRepair` — 잠금이 직렬화).
- 외부 대조 앱: 본 앱과 같은 탐지·복구 규칙(같은 SQL 의미 · 잠금 순서 · lock_timeout · 기록 테이블 `counter_drift_log`·`counter_reconcile_run`의 source 구분). 공유 = `reconcile-core/` 모듈(두 앱이 같은 코드를 의존 — 복사 금지).
- **저장소 구조 변경(task 04b)은 동작 무변경 리팩토링**(`playbooks/refactoring.md` 고정 순서): 보존 동작 = 앱 이미지의 동작·API·DB 스키마·설정 기본값 · 과거 하네스(ADR-001~011)가 새 경로에서 같은 계획·렌더를 만든다 · 테스트 508개 green(이동 전 baseline 선행) · 이미지 안 jar의 클래스 목록 diff 0(공통 모듈로 옮긴 패키지는 이름 유지). `git mv`로 이력 보존. .164 동기화 경로(`~/labs/seat-reservation-lab`)는 그대로.
- 대조는 앱 1대(또는 외부 앱 1대)에서만 돈다 — 여러 인스턴스는 범위 밖.
- 가설·판정 기준(성공 기준·고르는 규칙)은 측정 전에 ADR에 고정·커밋한다.
