## 다음 작업 후보 (우선순위순)

### N1. ADR-001 정합성 판정 + k6 하네스 — 우선순위: 높음 · 이후 모든 ADR의 판정 기준

- **왜 다음인가**: ADR-000은 단일 요청만 검증했다. 동시성 문제를 "관측"하려면 부하 도구와 정합성 판정이 먼저 있어야 한다 (`docs/adr/ADR-001-consistency-oracle.md`).
- **발생 가능한 문제**:
  - 현재 테스트는 모두 단일 요청 — k6의 HTTP 성공률만 보면 중복 선점이 드러나지 않는다(좌석 테이블은 HELD 하나로 보이고 홀드 행이 여럿 생기는 구조).
  - 로컬 실행 경로가 `bootTestRun`(Testcontainers)뿐이고 컨테이너 이름·포트가 매 실행 바뀐다 — 시드·판정 SQL을 붙일 고정 DB가 없다.
  - Seat 애그리거트가 홀드를 `@OneToMany`로 로드한다 — 부하 시 좌석 로드 쿼리 수가 측정값에 섞일 수 있다(스모크에서 관측한 구조, 수치 미측정).
- **방법론 선택지**:

| 방안 | 요지 | 비용 | 실패 모드 | 맞는 조건 |
|------|------|------|----------|----------|
| A | docker-compose 고정 Postgres + 시드 SQL + 판정 SQL 스크립트 | 낮음 | 환경 드리프트 | 로컬 반복 측정 |
| B | Testcontainers 재사용 컨테이너 + 판정 엔드포인트 | 중간 | 측정 대상 앱에 검증 코드가 섞임 | 앱 안에서 판정하고 싶을 때 |

- **권장 대처**: A — 측정 대상(앱)과 판정(SQL)을 분리한다.
- **착수 전 확인할 것**: 시드 규모(10,000석 전부 vs 축소), 반복 횟수, 결과 기록 위치(ADR 문서 본문 vs 별도 결과 파일). k6는 설치돼 있음(`/usr/bin/k6`).
