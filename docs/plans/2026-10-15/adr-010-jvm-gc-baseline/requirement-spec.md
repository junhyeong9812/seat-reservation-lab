## 0. 요구사항 원문 (인터뷰 기록)

- 원문(2026-10-15): "위 설명은 별도 문서로 간단하게 작성해주고, 정리하면 현재 애플리케이션 램할당이 적어서 시리얼라이즈 jvm으로 설정되어서 처리량의 문제가 생겼고 G1을 할당하는 최소 자원으로 재구동 후 간단하게 1회씩만 테스트 해보면 이를 확정지을 수 있다는거면 ADR10으로 위 설명을 위에 적고 그렇게 간단하게 실험 한번만 돌려보자. 이건 1회면 충분할 꺼 같고, G1 JVM 최소 할당 자원의 기준을 잡아서 해당 기준으로 서버를 띄우는 기준으로 만들면 좋겠네. 이 기준을 잡는 ADR 10 진행하자"
- 메인 정정(사용자에게 보고): 처리량은 줄지 않았다(tmpfs 4,200건/s = 도착률). 문제는 **꼬리 지연** — 약 47초마다 Full GC 72~108ms 정지로 그 초의 최대 응답 150~300ms.
- Q/A(2026-10-15):
  - 번호 → **새 ADR-010**, 기존 ADR-010~016은 011~017로 한 칸씩 민다.
  - 조건 → **4조건 사다리** 각 1회: ① 1g 기본(Serial) ② 1g + `-XX:+UseG1GC` ③ 1792m 기본(JVM 자동 G1 경계 기대) ④ 2g 기본.
  - 기준 정의 → **G1 명시 + 꼬리 지연 기준**: 자동 선택에 기대지 않고 `-XX:+UseG1GC`를 명시, 그 위에서 정상 구간 Full GC 0 · 가장 나쁜 1초 p99가 평소 수준인 최소 메모리.
  - 적용 범위 → **ADR-010 이후 측정부터**(ADR-001~009 하네스는 그대로) + 앱 기본 실행 설정(Dockerfile)에도 반영.

## 1. 목표·대상 (필수)

seat-reservation-lab에서 ① GC 설명을 머리에 둔 `docs/adr/ADR-010-jvm-gc-baseline.md`를 쓰고(기존 010~016 → 011~017), ② ADR-009 하네스에 앱 메모리·JVM 옵션 손잡이를 더해 S4c4200 tmpfs(고정 도착률 4,200건/s, DB 메모리) × 4조건 × 1회를 서버(.164)에서 재고, ③ 결과로 "앱 JVM 기준(수집기·메모리)"을 정해 ADR-010 결정과 Dockerfile 기본 실행 옵션에 반영하면 끝.

## 2. 경계·불변식 (필수)

- **손잡이 기본값은 기존 동작과 같다**: 새 손잡이를 주지 않으면 compose 렌더 결과(JAVA_TOOL_OPTIONS·mem_limit)가 지금과 바이트 단위로 같다 — ADR-009 재실행 재현성.
- 회차는 앱 기본값 조건(`--cond default` — A+C·정리 ①·판매 마감 켬, ADR-009 결정)으로 잰다.
- 실험 조건마다 실제 수집기·힙 최대치를 결과에 기록하고(`gc.json` collector, `-Xlog:gc,init`), 기대와 다르면(예: ③이 G1이 아님) 그대로 결과로 적는다 — 덮어쓰거나 재해석하지 않는다.
- 1회 측정임을 문서에 명시(반복 없음 — 사용자 결정). 판정은 Full GC 수·GC 정지 최대·가장 나쁜 1초 p99처럼 회차 하나로 뚜렷이 갈리는 지표 위주.
- ADR-001~009 compose·결과는 바꾸지 않는다(번호 변경에 따른 문서 참조 갱신은 예외).

## 3. 기준소스 (필수)

- 비교 기준: ADR-009 재측정 `k6/ADR-009/results/20261014-adr009-remeasure-e9146773` (1g Serial, S4c4200 tmpfs) — 단 같은 하네스 SHA로 ①도 다시 잰다.
- JVM 동작: 회차의 GC 로그(`-Xlog:gc*,safepoint`)가 정답. 자동 선택 경계(서버급 기계 판정 — CPU 2개 이상·메모리 약 1792MB 이상)는 실측으로 확인한다.

## 5. 검증 방법 (필수)

- 렌더 비교: 손잡이 없이 `docker compose config` 결과가 변경 전과 같다(diff 0).
- 스모크: 손잡이 지정 회차 1개에서 gc.json collector가 G1, mem_limit 반영 확인.
- 테스트: 전체 테스트 실행(Dockerfile·하네스만 바뀌어도 회귀 확인) — 508/0/0 기대.
- 본측정: 4조건 각 1회 `ok`, 조건별 표(수집기·힙 최대·Full GC 수·GC 정지 합/최대·p99·가장 나쁜 구간 p99·램프 p99·RPS·앱 CPU·앱 메모리 사용).
- 리뷰: 하네스 diff 듀얼 1패스(中) + 결과 문서 듀얼 1패스.
