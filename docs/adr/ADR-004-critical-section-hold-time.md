# ADR-004: 임계 구역 길이와 락 보유 시간 — 트랜잭션 안에 느린 작업이 끼면

- 상태: 가설 (Hypothesis) — 측정 계획(ADR-003 S6과 한 묶음으로 측정)
- 날짜: 2026-10-04
- 선행: ADR-002(기준선), **ADR-003(락 방식 11종 · S6 경합 강도 스윕의 지연 0 결과가 이 ADR의 기준)**
- 후행: ADR-007(확정 원자성 — 결제 확인이 트랜잭션 안에 있는가), ADR-008(확정 실패 보상)
- 명세: `docs/plans/2026-10-03/adr-003-lock-comparison/requirement-spec.md`(S6 재합의 2026-10-04)

## 1. 문제

ADR-003은 "같은 좌석에 경합이 몰릴 때 어떤 방식이 1명만 이기게 하고, 비용이 얼마인가"를 본다. 그런데 실서비스의 선점·확정에는 **DB 밖의 느린 작업**이 끼기 쉽다 — 결제 사전 승인 조회, 쿠폰·회원 등급 확인, 외부 재고 조회 같은 호출이 트랜잭션(또는 락) 안에서 수십 ms를 쓴다. 이때 질문이 바뀐다:

- **락을 쥔 채로 그 시간을 기다리는 방식**은 같은 좌석의 다음 요청을 그만큼 더 줄 세운다 — 대기형 DB 락이면 커넥션까지 쥔 채로.
- **락을 잡기 전에 기다리는 방식**(조건부 UPDATE·유니크)은 그 시간 동안 아무것도 막지 않지만, 진 쪽도 같은 시간을 쓴 뒤에야 진다.
- **충돌을 마지막에 아는 방식**(낙관락)은 진 쪽이 지연을 다 쓰고 버린다.

즉 이 ADR은 락 **방식**이 아니라 **임계 구역 설계** — 무엇을 락 안에 두고 무엇을 밖으로 뺄지 — 를 판정한다.

## 2. 실험 장치 — 임계 구역 지연

`seat.hold.critical-section-delay`(기본 0 — 기준선 불변). 선점 규칙(`HoldSeatProcess`)의 **1인 2매 확인 뒤, 상태를 바꾸기 직전**(ADR-003 §2.1의 ④와 ⑤ 사이)에 그만큼 `Thread.sleep` — 트랜잭션·커넥션을 쥔 채 외부 호출을 기다리는 것을 흉내 낸다. 측정값은 0 / 20ms.

같은 위치의 같은 지연이 방식마다 다른 구간에 걸린다(ADR-003 §2.13 기준):

| 방식 | 지연 동안 같은 좌석의 락을 쥐고 있나 | 지연 동안 커넥션 |
|------|--------------------------------|---------------|
| 1a jvm-lock · 8 redis-lock | 예(락이 트랜잭션 전체를 감쌈) | 이긴 쪽만 쥠, 진 쪽은 커넥션 없이 대기 |
| 1b jvm-lock-in-tx | 예 | 진 쪽도 쥔 채 대기 |
| 3a pessimistic · 6 advisory | 예(② 또는 ① 직후 획득) | 진 쪽도 쥔 채 대기 |
| 3b pessimistic-nowait | 예 — 진 쪽은 즉시 409 | 이긴 쪽만 |
| 2 conditional-update · 5 unique | **아니오**(락은 ⑤·⑦에서 — 지연 뒤) | 모두 쥠(경합은 지연 뒤에 판정) |
| 4 optimistic | 아니오(충돌은 ⑧에서 발견) | 모두 쥠, 진 쪽은 지연을 다 쓰고 버림 |
| 7 redis-nx | 예(관문 키는 ① 이전) — 진 쪽은 즉시 409 | 이긴 쪽만 |
| 0 none | — | 모두 쥠 |

## 3. 가설

| # | 가설 | 틀렸다고 판정할 관측 |
|---|------|------------------|
| H1 | 지연 20ms에서 **대기형 DB 락(3a·6·1b)** 은 진 쪽이 커넥션을 쥔 채 지연만큼 줄 서서 풀(10)이 고갈되고, **이웃 요청**(경합 없는 다른 좌석)의 지연·타임아웃이 지연 0보다 크게 는다 | 이웃 p99·에러율이 지연 0과 같다 |
| H2 | **즉시 실패형(3b·7)** 은 지연이 이긴 쪽에만 걸려 이웃 영향이 가장 작다 | 3b·7의 이웃 p99가 대기형과 같다 |
| H3 | **지연 뒤 판정형(2·5·4)** 은 진 쪽도 지연을 다 써서 같은 좌석 경쟁자 수(M)만큼 커넥션 시간이 늘지만, 줄 서지는 않는다 — 이웃 영향은 대기형과 즉시 실패형 사이 | 2·5·4가 대기형보다 나쁘거나 즉시 실패형만큼 좋다 |
| H4 | **커넥션 밖 대기형(1a·8)** 은 이웃 DB 지연은 작지만 Tomcat 워커가 대기열에 묶여 핫 좌석 수(K)가 클수록 이웃 지연이 는다 | K와 무관 |
| H5 | 정합성(이긴 수 = 좌석 수, 중복 0)은 지연과 무관하게 ADR-003 결과와 같다 — 1b는 지연이 '락 해제~커밋' 틈을 바꾸지 않으므로 중복 빈도도 비슷하다 | 지연에서 새 중복 |

## 4. 측정 계획

ADR-003 S6(경합 강도 스윕)과 **한 묶음으로** 잰다 — 같은 시기·환경에서 지연 0과 20ms를 재야 비교가 성립한다. 지연 0의 결과는 ADR-003, 0 vs 20ms 비교는 이 ADR이 분석한다.

| 대상 | 시나리오 | 단계 | 회차 |
|------|---------|------|------|
| 전략 11개 × 지연 0 / 20ms | S6: 핫 좌석 K(1·10·100) × 경쟁자 M=20, 핫 도착률 계단 200→3,200건/s + 이웃 500건/s | L4 | 3 |

판정 기준: 이웃 p99·에러율(타임아웃·연결 실패), 핫 이긴 쪽·진 쪽 지연, Hikari 대기·획득 대기, DB 락 대기, 이긴 수·중복(판정기 + 요청 기록의 일시 중복).
