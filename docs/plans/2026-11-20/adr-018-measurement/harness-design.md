# 하네스 설계 — ADR-018 2단계 task 02 (`k6/ADR-018/`)

> 정본은 명세 `requirement-spec.md`다. 이 문서는 하네스 워커에게 넘기는 메인의 설계 결정이다. 숫자는 [초안]이고, 측정 전 고정 커밋(task 03)에서 확정한다(그 전에는 로컬 dry-run · 스모크 근거로 바꿀 수 있음 — 바꾸면 log에 적는다).
> 선례: `k6/ADR-017/`(INTERFACE.md · plan17.py · paid-flow17.js · lib17.js · run17.sh · campaign17.sh · outcome17.py · summarize17.py · selftest17.py · compose.pay17.yml · lib17.sh). **구조 · 무효 규칙 · 회차 격리 · 시각 규약은 그대로 따르고, 바뀌는 것만 아래에 적는다.**

## 1. 셀 · 회차

- **방식(`method`)**:
  - `B0`: 1석 선점 API를 두 번 부른다(좌석 id 오름차순). 둘째가 실패해도 첫 석을 놓지 않는다(TTL로 만료).
  - `B1`: B0과 같다. 다만 둘째가 실패하면 `DELETE /api/holds/{holdId}`로 첫 석을 바로 놓는다.
  - `split` · `one-shot`: 묶음 API 한 번(`seat.hold-group.enabled=true` · `seat.hold-group.mode`를 회차마다 compose 환경으로).
  - B0 · B1 회차도 같은 이미지에서 돈다. B1의 해제 API에는 묶음 설정이 필요 없다.
- **겹침(`overlap`)**: `low` · `mid` · `high`(§2).
- **본 셀**: 4 방식 × 3 겹침 × rep 3 = 36회차.
- **경계 셀(`edge`)**: `split` · `one-shot` × rep 3 = 6회차(§4).
- **총 42회차.** 순서는 rep 안에서 방식 · 겹침을 회전한다(시간 효과와 섞이지 않게 — plan17 `--order` 방식).
- `--dry-run`으로 회차 시간과 총시간을 낸다. 총시간이 12시간을 넘으면 메인에 보고한다.

## 2. 좌석 · 겹침

- 회차 좌석 = 회차 하나 · section A · 한 줄로 이어진 번호.
- 세션 하나는 인접 2석 `(s, s+1)`을 노린다. 시작 위치 `s`를 아무 정수로 뽑으므로 `(s, s+1)`과 `(s+1, s+2)`처럼 한 석씩 겹치는 쌍이 생긴다(부분 겹침).
- 겹침 단계는 인기 구역의 크기 `H`(시작 위치를 뽑는 범위)로 조절한다.
  - `low`: `H` = 넓음([초안] 세션 수 × 3석 — 겹침이 드묾).
  - `mid`: [초안] `H` = 세션 수 × 0.5.
  - `high`: [초안] `H` = 세션 수 × 0.1.
  - 값은 로컬 · .164 스모크에서 단계 사이 성공률이 실제로 갈리도록 고정한다(가정 1).
- 좌석 재고는 `H` + 여유(나머지 좌석은 아무도 노리지 않음 — 정합 검사 대상에는 포함).
- 시작 위치 · 세션 종류 · 시간 값은 (회차, 세션 번호) 시드로 정한다(재현 · 시드 대조).

## 3. 세션 종류 · 흐름 (본 셀)

| 종류 | 비율 [초안] | 흐름 |
|---|---|---|
| `ok` | 70% | 2석 선점 → 결제 시작 → mock PG `pay` → 확정 |
| `abandon` | 15% | 2석 선점 뒤 아무것도 안 함(만료 배치가 정리) |
| `release` | 15% | 2석 선점 → [초안] 2~5초 뒤 해제(묶음 = 묶음 해제 · B0 · B1 = 1석 해제 2번) |

- 결제 단위:
  - 묶음(split · one-shot) = 결제 1건(묶음 결제 시작 · 묶음 확정 · PG 금액 2 × amount).
  - B0 · B1 = 좌석마다 결제 1건(1석 결제 시작 · 확정을 2번 — 지금 1석 API 그대로).
- 선점에 실패한 세션(2석을 다 못 잡음)은 거기서 끝난다.
  - B0: 첫 석을 잡은 채 끝난다.
  - B1: 첫 석을 해제하고 끝난다.
  - 묶음: 잡은 것 없음.
- 대기 시간(선점 → 결제 시작 · 결제 → 확정)은 ADR-017 `ok` 세션 분포를 그대로 쓴다.
- 보상 모드 `refund` · PG 주입 없음.

## 4. 경계 셀 (`edge` — 남은 위험 1 · M18-5)

- 목적: 만료 시각 경계(이쪽 now < E ≤ 배치 now)에 묶음 결제 시작 · 확정이 만료 배치와 겹치는 빈도를 센다.
- 설정 옵션(기존 키만 · 기동 검사 통과): `seat.hold.ttl` · `seat.hold.expiry-interval` · `seat.confirm.payment-window` · `payment-min-remaining` · `pay-by-margin`을 짧게 둔다.
  - [초안] TTL 8초 · 배치 1초 · W 6초 · θ 1초 · M 1초.
  - 기동 검사: M ≤ θ · θ < TTL · θ < W.
- 세션:
  - 절반은 선점 직후 결제 시작 → 결제 → **연장된 만료 시각 E 직전 ±0.5초에 확정**.
  - 절반은 **선점의 E 직전 ±0.5초에 결제 시작**.
  - 겹침은 `low`(교착은 겹침이 아니라 만료 배치와의 경쟁이다).
- 세는 것: `seat.db.deadlock{path}` 증가분 · 5xx 수 · 거부된 확정의 보상(refund) 완료 · M18-1 정합.
- 이 셀의 5xx(40P01)는 회차 무효 사유가 아니라 측정값이다. 다른 5xx는 무효다.

## 5. 회차 판정 (M18-1 · M18-3)

- 정합(회차마다 — 실패면 회차 `ok`이되 판정 실패로 기록):
  - `/internal/consistency` 위반 필드 0.
  - 부분 선점(묶음 홀드 수 ∉ {0, 2}) 0.
  - 이중 판매 0.
  - 돈 받고 좌석 없음 0 — refund CLOSE 완료 대기 뒤.
  - 카운터 = 홀드 + 예약.
  - 본 셀 5xx 0.
- 무효(재측정): k6 연결 오류 1건 이상 · 계획 세션 수 ≠ 분류 세션 수 · 시드 대조 불일치 · 필수 파일 결손 · 앱 기동 실패 · PC 링크 끊김.
- 지표 대조:
  - k6가 받은 `X-Seatlab-Reject` 헤더 합 = `seat.hold.rejected`(1석) · `seat.group.hold.rejected`(묶음 — 헤더 `group-*`).
  - `seat.group.request{op, outcome}` 합 = k6 요청 수(op별).
  - 맞지 않으면 무효.

## 6. 요약 (`summarize18.py`)

- 방식 × 겹침 표:
